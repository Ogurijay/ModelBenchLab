# DIGI-RUMBLE 完整可玩版设计文档

> 文档版本：2026-07-19
> 产品定位：以 Three.js 实现的本地同屏 2.5D 平台格斗游戏，精选复刻《Digimon Rumble Arena 2 / Digimon Battle Chronicle》的进化、能量争夺、危险场地与四人乱斗体验。
> 实现事实源：`src/data/gameData.js`、`src/app/GameFlowController.js`、`src/game/BattleSimulation.js`、`src/game/InputController.js` 及对应服务、渲染和测试文件。

## 1. 产品目标

DIGI-RUMBLE 不是单场技术演示，而是一条可从标题画面进入、选择模式和角色、完成比赛、获得解锁并继续游玩的产品闭环。

核心体验支柱：

1. **双攻击博弈**：所有攻击输入归为普通攻击与远程攻击，命中会掉落可用于进化的能量。
2. **三形态节奏变化**：八条普通角色谱系都有基础、第二、最终三个真实模型形态；最终形态再次满槽可释放 Ultra（究极技）。
3. **平面生存压力**：共享侧视的 2.5D 平台严格锁定纵深，横向越界或坠落会直接损失一条生命。
4. **场地也是对手**：五个竞技场各有一种有预警、可学习、结果确定的机关。
5. **短局与长期目标并存**：自由乱斗负责快速重玩，六战数码杯负责解锁、记录与结局。
6. **本地聚会可玩**：战斗内核支持 1–4 名人类或 CPU 斗士，键盘最多两套布局，并支持最多四个标准手柄。

## 2. 核心产品循环

```text
启动 → 标题 → 主菜单 → 模式 → 角色 → 场地/杯赛轮次
     → 预载本局形态 → 1–4 人战斗 → 结算 → 解锁/重试/下一轮
```

一局的微循环是：

1. 在单一 X/Y 平面内左右走位、跳跃，避开对手和机关。
2. 用普通攻击或远程攻击命中，迫使目标掉落能量数据。
3. 拾取能量，蓄满 100 点后自然进化。
4. 进化后用更高伤害和速度压制；最终形态满槽释放范围 Ultra。
5. 通过 HP（生命值）归零或平台越界制造 KO（击倒）。
6. 按当前规则结算生命、得分或进化竞速进度。

## 3. 双层状态机

### 3.1 产品流程状态

`GameFlowController` 是唯一流程事实源，只允许表内的显式跳转；非法跳转抛出 `InvalidFlowTransitionError`，避免界面和战斗状态脱节。

| 状态 | 中文含义 | 主要出口 |
| --- | --- | --- |
| `boot` | 启动与服务初始化 | `title` |
| `title` | 标题页 | `menu` |
| `menu` | 主菜单 | `mode`、`lab`、`options`、`title` |
| `mode` | 模式选择 | `menu`、`character`、`lab`、`options` |
| `character` | 角色/参战者配置 | `mode`、`stage`、`cup`、`menu` |
| `stage` | 自由战场地选择 | `character`、`battle`、`menu` |
| `cup` | 数码杯路线与当前轮次 | `character`、`battle`、`menu` |
| `battle` | 正在战斗 | `pause`、`result`、`menu` |
| `pause` | 暂停菜单 | `battle`、`menu` |
| `result` | 单局结算 | `battle`、`cup`、`stage`、`ending`、`menu` |
| `ending` | 杯赛结局 | `menu`、`title` |
| `lab` | 角色/形态资料库 | `menu`、`mode` |
| `options` | 设置 | `menu`、`mode` |

三种产品模式为杯赛（`cup`）、自由乱斗（`free`）和训练（`training`）。暂停不是新开一局，而是保留同一个模拟快照后停止推进。

### 3.2 单局状态

一局依次经历 `ready → battle → ended`；`paused` 是可逆标志。仅 `battle` 且未暂停时推进固定步长、CPU、投射物、拾取物和机关。结算后模拟保持只读，流程控制器再决定重试、下一轮或退出。

## 4. 角色与进化

| 谱系 | 基础形态 | 第二形态 | 最终形态 |
| --- | --- | --- | --- |
| 亚古兽系 | Agumon | Greymon | WarGreymon |
| 加布兽系 | Gabumon | Garurumon | MetalGarurumon |
| 基尔兽系 | Guilmon | Growlmon | Gallantmon |
| 巴达兽系 | Patamon | Angemon | Seraphimon |
| 迪路兽系 | Gatomon | Angewomon | Ophanimon |
| V 仔兽系 | Veemon | ExVeemon | Imperialdramon FM |
| 妖狐兽系 | Renamon | Kyubimon | Sakuyamon |
| 甲虫兽系 | Tentomon | Kabuterimon | HerculesKabuterimon |

八条常规谱系均绑定三个独立 GLB（glTF 二进制模型）资源，进化不是放大同一模型，而是切换真实形态和对应动画。Diaboromon（帝阿波罗兽）与 Apocalymon（启示录兽）是杯赛解锁的单形态 Boss；它们不会被伪造为三段形态，满能量时直接进入 Ultra 判定。

进化槽范围为 0–100：基础形态满槽升至第二形态，第二形态满槽升至最终形态；最终形态满槽触发 Ultra 后清空槽。被 KO 后若仍可重生，则下降一个形态层级，最低回到基础形态。

## 5. 战斗系统

### 5.1 空间、HP 与 KO

战场为共享侧视 2.5D：逻辑横轴为 X、竖轴为 Y，所有斗士、投射物、掉落物、道具和机关判定的 Z 坐标都固定为 `platform.laneZ`（默认 0）。镜头正对这一平面，不允许用纵深输入绕位。HP（生命值）归零，或跌出横向/纵向平台边界，都会产生 KO。除训练模式外，按规则扣除生命或累计击倒后在出生点重生。

### 5.2 基础动作

玩家基础动作是左右移动、跳跃、普通攻击、远程攻击和自然进化。攻击方式只有两种：普通攻击负责近距离连续压制，远程攻击发射沿 X 轴移动的投射物。玩家输入和战斗 HUD 不再提供纵深移动、闪避、Guard（防御）或 Heal（治疗）；模拟层仍兼容旧指令字段，以避免破坏历史测试或外部调用。

### 5.3 能量、进化与 Ultra

攻击命中会让受击者掉落可争夺的能量，拾取者才能获得。普通谱系按当前真实 `formIndex`（形态索引）进化；最终形态再次满槽时，Ultra 对所有敌方目标造成范围伤害并产生独立视听事件。单形态 Boss 满槽后直接 Ultra。模拟同时支持投射物命中任意敌方目标，而非锁死某一个对手。

设置项 `freeEvolutionCheat` 默认开启。开启时，战斗 HUD 为主玩家显示“退化 / 进化”按钮；按钮调用 `BattleSimulation.forceForm(fighterId, direction)`，在真实形态数组的有效范围内立即升降一阶，不消耗能量，也不会越过基础或最终形态边界。该接口发出带 `forced: true` 的 `evolution` / `devolution` 事件，确保模型、文字、特效与音效同步。

### 5.4 战斗拾取物

模拟层只接收四个稳定运行时类型，展示层可把具体图标或道具名称映射到它们：

| 运行时类型 | 中文效果 |
| --- | --- |
| `energy` | 立即补充进化能量 |
| `health` | 回复 HP |
| `power` | 提供短期输出增益 |
| `life` | 增加一条剩余生命 |

`gameData.ITEMS` 的展示 id 与 effect 已对齐上表语义；其中 `evo-orb` 的运行时 effect 是 `energy`，其余为同名 effect。进入 `BattleSimulation` 时必须传 effect 类型，不能把展示 id 当作模拟类型。

## 6. 四种比赛规则

| 规则 | 胜负目标 | 结束条件 |
| --- | --- | --- |
| Stock / 生命制 | 保住最后一条生命 | 只剩一名未淘汰斗士；若先到时限，则按剩余生命、HP、得分、形态、能量排序 |
| Timed / 限时制 | 在时限内取得最多击倒 | 计时归零；按得分、HP、形态、能量破同分 |
| Race / 进化竞速 | 最先完成目标次数的进化/究极循环 | 任一斗士达到 `raceTarget` |
| Training / 训练 | 无失败地练习动作和资源选择 | 玩家主动退出，不自动结算 |

自由乱斗可选择规则、场地、CPU 难度和参战人数；杯赛由每轮配置锁定规则与对手；训练模式提供无限计时、持续满能量与不扣生命的重生，便于重复验证招式。

## 7. 五个竞技场与机关

机关由固定种子、间隔和序列驱动；相同输入与种子得到相同结果，便于训练和自动测试。界面应先给颜色、区域或落点预警，再结算伤害。

| 场地 | 机关 | 行为与对策 |
| --- | --- | --- |
| 网络终端 | `pulse` 数据脉冲 | 周期打击中央半径并产生推力，提前离开中心 |
| 熔岩核心 | `lava` 熔岩带 | 吞没指定的狭长区域，观察预警后换位 |
| 齿轮工厂 | `laser` 扫描激光 | 依次扫过 -5、0、5 三条横向位置，避开当前扫描线 |
| 遗迹丛林 | `rocks` 锁定落石 | 按确定顺序锁定在场斗士，并伤害落点半径内所有人 |
| 黑暗区域 | `void` 虚空侵蚀 | 平台边缘成为致命区且无视无敌，只在杯赛决战开放 |

机关可以造成 KO，但不会把击倒奖励错误记到最后一名攻击者。渲染层只表现模拟发出的 `hazard` 与 `hazardHit` 事件，不另行计算胜负。

## 8. CPU 与本地多人

模拟支持 1–4 名斗士，可分别配置为 `human`（人类）或 `cpu`（电脑）；可选 `team` 字段用于过滤友方目标，但当前排名仍按单名斗士结算。CPU 会在同一平面选择最近的有效敌人，使用左右移动、跳跃、普通攻击、远程攻击、进化和 Ultra，而不是固定追逐 P1。

| 难度 | 中文定位 | 行为差异 |
| --- | --- | --- |
| `rookie` | 新手 | 思考间隔长、进攻欲和移动速度较低 |
| `normal` | 标准 | 平衡反应、进攻和速度 |
| `veteran` | 老练 | 更短决策间隔、更积极、更快 |

键盘提供两套互不冲突的布局；标准 Gamepad API（手柄接口）按浏览器当前返回顺序读取最多四个手柄。正式游玩前应在角色配置页确认设备顺序；当前实现未持久化断线手柄与角色槽位的绑定。

## 9. 六战数码杯

杯赛进度只有胜利才前进；失败或平局停留在当前轮。每轮胜利立即写入奖励，完成第六轮后进入结局状态。

| 轮次 | 名称 | 场地 / 规则 | 对手 | 奖励 |
| --- | --- | --- | --- | --- |
| 01 | 网络预选 | 网络终端 / 生命制 2 条 | Gabumon | 解锁熔岩核心 |
| 02 | 三方混战 | 熔岩核心 / 限时 75 秒 | Guilmon、Patamon | 800 DATA，并解锁遗迹丛林 |
| 03 | 进化竞速 | 遗迹丛林 / 目标 2 | Gatomon、Renamon | 解锁齿轮工厂 |
| 04 | 最终四强 | 齿轮工厂 / 生命制 2 条 | Veemon、Gabumon、Tentomon | 1200 DATA |
| 05 | 黑客乱入 | 网络终端 / 生命制 3 条 | Diaboromon | 解锁 Diaboromon |
| Ω | 终焉决赛 | 黑暗区域 / 生命制 3 条 | Apocalymon | 解锁 Apocalymon、黑暗区域与冠军徽章 |

## 10. 解锁、存档与设置

`SaveService` 使用版本化 JSON 存档，浏览器键为 `digi-rumble.save`，结构包含 DATA、角色/场地解锁、徽章、杯赛进度和比赛统计。初始开放八条常规谱系与网络终端；Boss 和其余场地按杯赛解锁。服务支持旧版本迁移、拒绝读取未来版本，并在 `localStorage` 不可用时退回内存存储。

`SettingsService` 使用 `digi-rumble.settings`，保存 CPU 难度、主/音乐/音效音量、镜头震动、30–300 秒战斗时长、低/中/高图形质量、减少动态效果、高对比度、提示、语言与按键映射。设置与进度分开版本化，重置设置不会清除解锁。

比赛结束后至少写入模式、胜负、角色、最大连击、时长和伤害；杯赛另外记录当前轮、失败次数和是否完成。存档写入失败应以可见提示降级，不能阻断当前本地对局。

## 11. UI、音频与资源加载

### 11.1 界面信息架构

`GameUI` 按流程状态渲染标题、菜单、模式、角色、场地、杯赛、战斗 HUD（抬头显示）、暂停、结果、结局、资料库与设置。战斗 HUD 必须同时显示每名斗士的名称、形态、HP、能量、剩余生命/得分和当前规则；机关预警、进化、Ultra、KO 和解锁结果要有不依赖颜色的文字反馈。

键盘、手柄和点击都应能完成产品主流程。减少动态效果时停用非必要摇晃和强闪；高对比度模式提高文字、焦点和危险区边界可辨性。

### 11.2 音频

`AudioSystem` 以 Web Audio API（网页音频接口）程序化生成攻击、命中、守卫、治疗、进化、Ultra、KO、机关和暂停等提示；首次用户交互后才解锁音频上下文。当前不打包原作音乐或语音，且运行时仅接入一个主音量节点；设置服务虽保留音乐/音效音量字段，分通道混音仍属于后续接线项。

### 11.3 3D 资源

`AssetManager` 从本局所有参战谱系收集形态 URL，使用 `GLTFLoader` 预载并汇总进度；缓存原始 GLB，以 `SkeletonUtils.clone` 安全克隆蒙皮模型，并提供引用计数、卸载、中止和错误路径。`FighterView` 按 `formIndex` 切换真实模型，并通过语义动画映射选择待机、跑动、攻击、受击、进化等片段；缺少片段时使用安全回退。

加载失败必须指出具体资源并允许返回选择页；不能用空白画面伪装成功。场地几何、特效和 HUD 可以先创建，但只有形态资源就绪后才进入可操作的 `battle`。

## 12. 验收标准

### 12.1 自动验收

在项目目录依次执行 `npm test` 与 `npm run build`，必须全部成功且无未处理异常。自动测试至少覆盖：

- 1–4 人配置、三档 CPU、多目标近战和投射物；
- 普通/远程两类攻击、全实体纵深锁定、三段进化、最终形态 Ultra 与单形态 Boss Ultra；
- 生命制、限时制、竞速制、训练制、越界、重生和降阶；
- 五类机关的确定性结果、四类运行时道具、暂停与完整快照；
- 双键盘和四手柄输入边沿；
- 版本化存档/设置迁移、六轮杯赛奖励、非法流程跳转；
- 本局工厂对四人自由战、杯赛固定对手、Boss 单形态和结算摘要的映射。
- 自由进化作弊的免费升阶、降阶、边界保护与设置迁移。

### 12.2 浏览器手动验收

1. 从标题页仅靠键盘、仅靠鼠标、仅靠手柄各走通一次“自由乱斗 → 结算 → 重赛/返回”。
2. 以新存档完成六战杯赛，确认场地、两名 Boss、DATA、徽章与结局逐轮落盘；刷新页面后仍存在。
3. 在八条常规谱系各完成两次进化和一次 Ultra；用两名 Boss 验证满槽直接 Ultra、始终只有一个真实形态。
4. 分别触发五个机关，确认预警与实际命中区域一致，KO、排名和音效只结算一次。
5. 连接四个标准手柄，确认每个槽位只控制自己的斗士；再验证 P1/P2 键盘不会互相吞键。
6. 模拟 GLB 404、禁用 `localStorage`、禁用 Web Audio，确认有可理解的降级或错误界面且流程可返回。
7. 在 1280×720、1920×1080 以及窄窗口检查 HUD、菜单焦点和中文文字不遮挡；启用减少动态效果与高对比度再复查。
8. 点击战斗 HUD 的“进化 / 退化”，确认仅主玩家切换真实模型、能量不变，基础/最终边界会给出明确提示。

## 13. 与 PS2 原作差异

本项目是“精选内容复刻”，目标是复现核心决策和聚会乱斗节奏，不承诺角色、场地和规则逐项 1:1。对外介绍不得使用“完整移植”“原版重制”或“官方复刻”等措辞。

| 维度 | PS2 原作参考口径 | 本项目 | 取舍 |
| --- | --- | --- | --- |
| 战斗形态 | 常见攻略口径可推导为 47 个战斗形态：14 条三段谱系加 5 名单形态角色；这不等于 47 名都可在赛前独立选择 | 8 条三段谱系 + 2 名单形态 Boss，共 26 个 GLB 形态 | 保留三段进化广度，缩小角色测试矩阵 |
| 场地 | 攻略列出 10 个场地 | 5 个场地、5 种确定性机关 | 精选最能表达危险场地的五类机制 |
| 比赛规则 | 默认 Knockout 加 8 个隐藏 Match Types，共 9 种口径 | 生命、限时、进化竞速、训练 4 种 | 优先完整实现基础乱斗与进化竞速 |
| 多人 | 原作支持 2–4 人聚会乱斗 | 模拟支持 1–4 人；双键盘加最多四手柄 | 适配浏览器本地输入，不提供在线联机 |
| 内容结构 | 原作有自身角色解锁与多种隐藏内容 | 六战线性数码杯、两名 Boss 与五场地解锁 | 采用可验证的短流程，不复刻原作全部隐藏条件 |
| 表现与资产 | 原作包含其商业模型、音乐、语音与商标素材 | Three.js 渲染、外部来源 GLB、程序化音效 | 不复制原作音轨、语音、UI 图像或关卡文件 |
