## 技术方案

- 原生 ES 模块 + Canvas 2D,零运行时依赖,由根 vite 服务。逻辑分辨率 960×540,画布背板按窗口 × devicePixelRatio 放大(上限 2.5 倍),矢量绘制保持清晰。逻辑固定 60 帧/秒,rAF 渲染,标签页隐藏时 setInterval 兜底。
- **人物**:`skeleton.js` 以关节角(躯干前倾、头、双臂肩肘、双腿髋膝、全身翻转)做正向运动学,四肢用"粗描边折线"技法画出无接缝的赛璐璐肢体;头部为侧脸轮廓 + 动漫眼 + 分层刺发(每根刺单独描边再用发芯盖住内侧描边)+ 护额 / 面罩 / 虚面具;服装支持夹克、和服(死霸装)、马甲、高领、羽织(前后片随速度摆动)、黑袍云纹、袴;围巾 / 马尾 / 护额飘带用 Verlet 链在世界坐标模拟。武器(巨刃、太刀、锯齿刀、直刀、苦无、弓、手杖)挂在前手,挥砍时记录刀尖生成刀光拖尾。姿势库 63 个 + 程序化走 / 跑 / 呼吸循环,显示姿势每帧向目标插值。头像与 cut-in 用同一人物渲染放大并缓存到离屏画布。
- **招式数据**:招式为数据 + 回调:`poses` 关键帧、`hits` 打击框(相对朝向)、`vel` 速度脚本、`ev` 帧事件、`tick` 自定义逻辑、`cat`(N/U/I)决定取消规则。工厂函数:`fistSet` / `bladeSet`(徒手 / 持刀普攻套组,含连段、挑空、下段、空中三段与俯冲)、`rushLock`(突进锁定型奥义:蓄力 → 突进 → 锁定多段 → 终结击飞)、`trapMove`(在对手位置延迟生成陷阱,命中后由陷阱锁定目标多段)、`transform`(限时变身:伤害 / 速度 / 防御 / 查克拉回复倍率、换外观、爆发冲击)。共 10 角色 182 招(技能 40、必杀 40)+ 6 援助。
- **判定与规则**(`battle.js applyHit`):正面防御(普攻削 4%、技能 12%),格挡累计 >240 破防;COUNTER +15%;连击第 4 击起递减;硬直累积 >230 强制击倒;命中停顿双方冻结,输入缓冲在停顿期间不衰减;反击架势化解近身攻击;锁定(lock)可挂在角色或陷阱上,锁定者离开招式 / 陷阱消失即释放;飞行道具按 power 对消,结界 / 砂盾可吞掉敌方飞行道具。
- **奥义演出**:消耗气的招式触发全场冻结 44 帧 + 背景压暗 + 斜带 cut-in(人物大头像滑入 + 毛笔字招式名)+ 镜头推近;BGM 闪避(duck)。
- **AI**(`ai.js`):只操作虚拟手柄;四档难度决定反应间隔、防御 / 替身 / 受身 / 连段执行 / 失误概率;会识别威胁防御、贴身连段并命中确认取消必杀、挑空跳追、按招式 `ai` 提示(距离窗口与类型:飞行道具 / 突进 / 陷阱 / 对空 / 反击 / 变身 / 逃脱)挑选技能必杀、识破陷阱预兆冲刺或跳开、召唤援助。
- **场景与音频**:`stages.js`(8 张原创场景,多层视差 + 透视地面,预渲染静态层,每帧约 0.05–0.2 ms)与 `audio.js`(60 种合成音效 + 12 首原创配乐,前瞻调度、限流与限幅)由子任务按本项目接口实现,接口见文件头。

## 已知问题 / 限制

- CPU 对 CPU 胜率仍有差距(疾风 / 夜叉 / 雷牙偏弱,绯樱 / 鸦 / 狂剑偏强),人类对战的平衡未经真人测试。
- 战斗精灵逐帧独立生成,帧间细节有轻微漂移;动作为 19 个关键帧切换而非逐帧动画;变身不换精灵,只叠加气焰与染色。
- 音效与配乐只做了电平与无 NaN 的数值检查,未经人工试听。
- 未实现:网络对战、BVN 3.x 的角色中途换人 / 双人援助、特殊胜利演出与剧情模式;同角色对战只对 2P 换色。
- 2P 默认键位依赖小键盘,另提供 `, . / M ; '` 备用键;键盘冲突(部分键盘多键同时按下)视硬件而定。
