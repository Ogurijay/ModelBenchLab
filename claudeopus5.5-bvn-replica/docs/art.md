# 角色美术生成记录

`assets/art/` 中的角色美术由 **OpenAI Codex CLI 0.162.1 的 image_generation 工具**生成(2026-10-11),再经本地脚本后处理。全部角色为本项目原创设计;**这部分美术不是 Claude Opus 5.5 自身产出**,评测时需单独看待。场景、特效、界面、音效与音乐仍为代码生成。

## 经过

1. 先用 Grok Build(Imagine)试生成。首张按"金色刺发 + 胡须 + 橙色运动服 + 护额"描述的疾风直接画成了原作人物(含原作村落标志),已删除;改为原创造型描述后整套生成过一版,但用户认为画面质量不佳,且参考图编辑会沿用参考姿势,**Grok 版全部弃用并已删除**。
2. 改用 Codex CLI:画风更干净、背景是精确的纯绿,带参考图生成时也能按要求换姿势,同一角色各帧外观一致。
3. Codex 调用注意事项(本机):PATH 上同时存在旧版 WinGet `codex.exe`(0.116)与 npm 版,脚本直接调用 npm 版的 `node .../@openai/codex/bin/codex.js`;npm 版需 ≥0.162 才能用当前模型;`codex exec` 在非终端下会读 stdin,需传空 stdin;`--image` 可接多个值,提示词前要加 `--`。

## 原创性处理

- 去掉原作的标志性特征(护额纹章、胡须、红云黑袍、条纹帽、铃铛等),改为原创的发型 / 配色 / 服装(护目镜 + 红围巾、白挑染、砂色兜帽与陶瓮、银色新月纹长衣、暗红刺发等),只保留阵营气质与招式定位;
- 每条提示词附加"不得与任何现有动漫 / 漫画 / 游戏角色相似,无村落标志、无漩涡纹、无 logo、无文字";
- 人工逐张检查。游戏内程序化人物(`looks.js`,缺图时的回退)同步改为新造型配色。

## 资源与流程

| 类型 | 文件 | 生成方式 | 用途 |
|---|---|---|---|
| 全身立绘 | `full_<id>.webp`(16 张) | 文生图,纯绿底 | 标题、选人、VS、结算、援助角色出场 |
| 头像 | `portrait_<id>.webp`(16 张) | 以全身立绘为参考图 | 状态栏、选人格、出招表 |
| 奥义 cut-in | `cutin_<id>.webp`(10 张) | 以全身立绘为参考图,16:9 | 必杀发动时的斜带演出 |
| 战斗精灵 | `sp_<id>_<帧>.webp`(10 人 × 19 帧) | 以全身立绘为参考图(只取外观,姿势按描述) | 对战中的角色 |

1. 提示词:`tools/art_prompts.json`(角色外观 / cut-in 招式 / 打法类型 fist·blade·sand / 武器)、`tools/sprite_frames.json`(19 种姿势 × 三类打法)、`tools/gen_codex.py`(风格与原创性约束,`python tools/gen_codex.py full|portrait|cutin|sprite`,并发由 `CODEX_PAR` 控制)。原图存 `assets/raw_codex/`(已 gitignore)。
2. 后处理 `tools/process_art.py`:绿幕抠像(按绿色领先度生成 alpha,边缘去溢色)→ 按包围盒裁边 → 缩放(精灵 0.4 倍)→ WebP;同时写 `sprites.json`(每帧尺寸、脚底中心 x、包围盒高度)。`python tools/process_art.py sheet <id>` 输出按游戏内比例排版的检查图。
3. 运行时 `src/art.js`:按帧类型的目标身高比例归一化尺寸(持武器角色乘武器系数,`ADJ` 表可逐帧修正),地面帧脚底对齐、空中帧包围盒中心对齐;预烘焙白色受击闪光、纯色残影剪影、同角色对战 2P 色相换色;姿势名映射到 19 个精灵帧;缺图时回退到程序化骨架人物。

19 个精灵帧:idle、walk、run、jump、fall、crouch、guard、hit、knock、down、attack1、attack2、launch、sweep、airatk、cast、charge、lunge、victory。

## 局限

- 精灵逐帧独立生成,同一角色不同帧之间细节有轻微漂移;动作是关键帧切换而非逐帧动画,靠出招瞬间前帧淡出残影、待机呼吸、受击抖动补足连贯感。
- 生图尺度不一致,依靠帧类型目标比例归一化,个别帧可能偏大偏小。
- 变身(卍解 / 觉醒)不换精灵,只叠加气焰与染色。
