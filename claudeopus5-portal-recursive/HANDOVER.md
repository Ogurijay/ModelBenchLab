## 两个核心架构决定(也是本作与同题其它作答的主要差异)

### 1. 传送门 = 在碰撞世界里真的开一个洞

`src/sim/world.js` 在放门时,把门口那块矩形棱柱从所有相交的实体盒里做**布尔减法**
(`src/core/boxes.js` 的 `subtractBox`,一次减法产出 ≤6 块补集盒,已用 200 组随机样例验证体积守恒且互不重叠)。

由此得到三条性质:

- 门口以外的墙面**任何时刻都是实心的**,不存在「临时忽略某面墙」的窗口,也就不会出现
  「窗口切换的瞬间把实体从墙里挤出几米远」这一类经典事故;
- 能不能走进门,由门口是否落在脚下高度决定 —— 门底高于脚就得跳进去,和原作一致,不需要额外规则;
- 门的背面用一块**背板**封住,且只对「实体中心已经在门背面」的实体生效。正面穿越者在越过门面的
  同一个子步里就被传走,永远碰不到背板,所以开孔不会变成一条可双向步行的免费通道;
- **只有两扇门都在场时才开孔**。单扇门不成对、穿越逻辑不触发,此时若照样挖穿,墙里就会多出一个
  「进得去、不传送、出不来」的空腔(审查实测过:玩家会掉进地板门口被背板弹成无限抖动)。

开孔深度用「沿 −N 逐点步进、遇到第一个空点就停」求出,只挖穿与门面**连续**的那层材料;
取「所有与探针体相交的盒的最深点」会被一块恰好掠过边缘的地板带偏,把墙背后的空气也挖了。
放门前还有两道校验:`apertureClear`(门口正前方 3×3 采样不得撞到相邻的垂直墙,堵住内角处
「门口一半埋进侧墙、从这扇门出来会被挤出地图」的坑)与 `aperturesOverlap`(用世界 AABB 判两个
门口是否相交,对称且与各自朝向无关)。任何一次开孔/补孔之后都会对玩家与方块跑一遍 `unstick`:
先温和推、再六向挤,实在不行送回出生点 —— 宁可传送玩家,也不允许「位置永久冻结、只能按 R」。

关卡本身的门洞、观察窗也用同一套减法生成(`level.cuts`),渲染与碰撞共享同一批盒 ——
不会出现「看着是洞其实撞墙」。白色面板放在 `level.overlays`(挖洞之后才叠加),免得被自己的 cut 削掉。

### 2. 两层递归门景

`src/gfx/portals.js` 每帧由深到浅渲染:

```
level 2 → 漩涡占位画进 rt[P][2](半分辨率)
level 1 → 场景里的 P 门贴 rt[P][2],画进 rt[P][1]
主画面   → 场景里的 P 门贴 rt[P][1]
```

第 n 层的虚拟相机 = 主相机连乘 n 次穿越矩阵(`throughMatrix`,与物理用的纯函数同构,自测第 2 组交叉校验);
每一层都用 Lengyel 斜近裁剪把出口门背后的几何切掉。门盘用超椭圆(|x|⁴+|y|⁴≤1)裁形,
与物理门口的矩形一致 —— 视觉能穿的地方物理一定能穿。

## 数值与防作弊口径

- 玩家半尺寸 (0.3, 0.9, 0.3)(即宽 0.6m、高 1.8m),眼高 1.55m;g=18,走速 4.6,跳速 6.0
  → 跳高 1.0m、**中心跳距约 3.07m**。落地只要 AABB 边缘搭上对岸,两侧各多算半宽 0.3m;
  土狼时间 COYOTE=0.1s 又允许走出边缘后再起跳(多给 4.6×0.1≈0.46m)。
  **合计:普通跑跳的有效极限约 4.1m。**
- C4 深渊 7m、C5 深渊 7.6m —— 都远超 4.1m,飞跃不可被普通跳跃绕过(`npm test` 里有专项用例:
  在 6 个不同起跳时机上尝试跨越,全部坠落);台阶助爬只在着地时生效,空中不会「白送」落点。
- 飞跃弹道:高台顶 7.5m → 落到地面门面时约 17.4 m/s;发射墙白板带只有 y∈[5,8],门心被夹在
  [6.04, 6.96]。出口速度 = 竖直下落分量转成水平 + 进门时的水平分量转成竖直:
  · 上向量与冲刺同向(顺手的打法)→ 竖直分量是**抬升**,射程约 14~18m,落点 z ≈ −17;
  · 上向量与冲刺相反(从对侧开的枪)→ 竖直分量是**下坠**,射程掉到约 9.7m,落点 z ≈ −8。
  深渊按后者的下限定宽,所以两种打法都能过 —— 这也是回归用例「逆向上向量的飞跃也能过深渊」的口径。
- 地面门的上向量吸附到开枪时的视线主轴,门口 2m 的长轴因此通常与冲刺方向一致,落点容差 ±1m。

## 回归测试

```bash
npm test        # 等价于 node tests/run.mjs,不需要浏览器
```

覆盖:10 组冻结用例、盒减法性质(400 组随机:体积守恒 / 补集互不重叠 / ≤6 块)、
关卡几何审计(出生点、方块、白面板尺寸、天花板门可放置性)、五关可解性(编程走完预期解法)、
防作弊下限(6 个起跳时机都跨不过深渊),以及一组「审查发现过的坑」回归用例
(单门不开孔、内角门被拒、换门后不被封死、逆向上向量仍能飞过、过场中重置能拉回状态机)。


`game.player.keys.KeyW = true` + `stepFrame(n)` 走路。

## 已知限制

- 传送门枪的射线打在**未开孔**的原始几何上,所以不能「透过自己的门再打一枪」(原作可以)。
- 方块视觉恒轴对齐(不翻滚);玩家推不动地上的方块(可拾取、可站上去)。
- 门只放在轴对齐面上(本仓关卡无斜面);地面/天花板门的上向量会吸附到世界主轴。
- 玻璃用普通半透明材质(不做 transmission):一帧要跑 5 遍场景,折射太贵。
- 指针锁在无头自动化环境不可用(环境限制),但整局可用 `__bench` 编程驱动。
