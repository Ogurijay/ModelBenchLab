# 数据来源与不确定性说明

## 目的

本项目把两千多年历史压缩为可交互 3D 沙盘。任何这类压缩都会包含取舍，因此本文件明确哪些内容来自史实概括、哪些属于推定复原、哪些仅是程序化生成，避免视觉精细度被误读为史料精确度。

项目不在运行时抓取外部网络数据，不复制某一历史地图的原始矢量边界，也不把程序生成建筑称为遗址或古建复原。

## 数据层级

### 1. 历史关键帧

12 个关键帧用于组织叙事，并非宣布只有这些年份重要：

| 内部年份 | 名称 | 用途 |
|---:|---|---|
| -770 | 春秋初期·周室东迁 | 起点与诸侯格局 |
| -300 | 战国七雄·兼并时代 | 多势力兼并 |
| -221 | 秦统一·郡县帝国 | 第一次大一统锚点 |
| 2 | 西汉成熟期·丝路贯通 | 帝国与丝路 |
| 229 | 三国鼎立·山河为界 | 分立与地理屏障 |
| 750 | 盛唐都会·四方汇聚 | 都会与交流 |
| 1142 | 宋金对峙·南北分治 | 多政权并立 |
| 1279 | 元朝一统·欧亚通衢 | 统一与欧亚联系 |
| 1421 | 明初迁都·两京格局 | 两京与明式城市 |
| 1759 | 清代高峰·多元疆域 | 多元疆域概括 |
| 1912 | 共和转型·战争年代 | 近代制度与城市转型 |
| 2025 | 现代中国·城市群时代 | 当代城市群展示 |

时间轴位于两个关键帧之间时，所有连续变化都属于视觉推演。离散政权更替、战争和制度变化不应被线性插值解释为真实过程。

### 2. 势力与疆域

- 政权名称、代表性都城和重大事件来自常见历史分期与主流史学概括。
- 为适配实时渲染，疆域使用低顶点数量的示意多边形，省略飞地、羁縻关系、季节性控制、军事前线摆动和许多地方势力。
- 古代“疆域”往往是控制力梯度，不等同现代主权边界；边线只是交互沙盘的概括表达。
- 对存在争议或资料不足的区域，应使用推定标签、虚线、透明度或详情说明，而不是伪造精确坐标。
- 现代帧不得被宣传为法定地图服务；涉及现实边界时只提供概括背景。

### 3. 城市与建筑

- 代表城市的存在、历史地位和大致区域属于历史概括。
- 城市范围、道路走向、城墙尺度和建筑密度通常经过归纳，不是考古平面图。
- 建筑原型表达时代可辨识特征，例如礼制轴线、城墙与坊市、院落与屋顶形制、近代街区或现代高层，但不声称复原具体单体。
- 城市中的普通建筑、树木、道路细节和人造地标组合由固定 seed 生成。
- 程序生成器必须接受时代、城市等级、地形类型、气候区和水系邻近度等约束，禁止把现代高层放入古代关键帧或让山城套用平原规则。

### 4. 地形与水系

- 山脉、盆地、平原、主要河流和海岸用于建立宏观空间关系。
- 本项目不是 DEM（Digital Elevation Model，数字高程模型）或水文模拟；高度、河宽、坡度和岸线均可能夸张，以便在全国尺度辨认。
- 城市地形可由区域基底与确定性噪声叠加，属于程序化生成。
- 除非另有明确数据记录，河道迁移、海岸推进、湖泊消长不按逐年真实过程模拟。

### 5. 世界其他地区

- 世界层用于交代同期主要区域势力、交通联系和事件背景。
- 边界精度、城市数量和建筑精度都低于中国层。
- 世界层同样不能把古代影响范围画成现代精确国界。

## 三类对外标签

### 史实概括

适用于有较明确史学依据、但为沙盘尺度做过简化的内容。

示例：

- 某一关键帧的主要政权名称；
- 某座代表城市在该时期的政治或经济地位；
- 某项重大事件发生的大致年代；
- 经简化的核心控制区域。

界面措辞应使用“概括”“主要”“约”等，避免过度精确。

### 推定复原

适用于史料不完整、位置或形态存在争议，或项目需要补足连续视觉结构的内容。

示例：

- 城墙和道路的推定走向；
- 缺乏完整考古证据的建筑组合；
- 两个关键帧之间的势力边界形变；
- 资料不足地区的城市规模。

界面必须明确显示“推定复原”。

### 程序化生成

适用于由算法按规则生成、不对应某一项直接史料的内容。

示例：

- 普通民居、树木、街巷和农田；
- 全国视角下的城市天际线轮廓；
- 关键帧之间的建筑密度渐变；
- 为表现地貌而生成的局部起伏。

程序化生成必须可复现，并显示 seed 或稳定指纹；它只承诺“符合当前规则”，不承诺“历史上确实如此”。

## 内部字段映射

若数据层使用置信度字段，可采用以下映射：

| 内部字段 | 对外标签 | 备注 |
|---|---|---|
| `high` | 史实概括 | 年代、政权、城市等较明确，但仍经过可视化简化 |
| `medium` | 史实概括 | 在详情中补充“概括程度较高” |
| `inferred` | 推定复原 | 必须显示推定提示 |
| `generated: true` 或 `city.inferred: true` | 程序化生成 | 同时保存固定 seed |

一条记录可以同时具有历史骨架和程序化细节。例如“唐代长安是关键都城”可属史实概括，而页面中某条普通街巷和民居排列属程序化生成。界面应展示与用户当前查看对象最相关的标签。

## 资料依据与使用方式

历史内容应综合以下类型的资料进行人工概括：

- 通行中国历史年代、政权沿革和城市史资料；
- 历史地图集对主要政权与交通走廊的概括；
- 考古机构、博物馆和古建筑研究中的时代形制说明；
- 现代地理常识中的山脉、盆地、平原、河流和城市群关系；
- 世界史通行分期和重大事件年表。

这些资料只用于建立语义骨架与风格规则。若未来引入可再分发的数据集、纹理或模型，必须在本文件追加：

- 数据集或资产名称；
- 作者与发布机构；
- 版本和获取日期；
- 许可证；
- 实际使用字段或文件；
- 修改与简化方法。

未经许可证确认，不得把第三方地图、模型、纹理或图像直接打包进项目。

## 冲突与修订规则

1. 发现史实冲突时，不用随机结果“填平”；先降低置信度或标为推定。
2. 有多个合理解释时，默认展示一种，同时在详情说明存在其他观点。
3. 修订疆域、城市或事件时，记录修改理由和受影响关键帧。
4. 修订程序生成算法时保留 seed，并更新确定性测试基线。
5. 新增现代敏感边界前，先确认展示目的和合规要求；无法确认时保持概括表达。

## 用户可见免责声明

建议在帮助或“数据说明”面板中保留以下短文：

> 本沙盘以 12 个历史关键帧进行概括展示。关键帧之间为程序化推演；疆域、城市与建筑均经过可视化简化。标记为“推定复原”或“程序化生成”的内容不代表确定史实。本项目不是 GIS、考古或法定地图产品。
