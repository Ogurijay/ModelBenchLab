# 浏览器验收场景

## 目标

本文件定义可重复的真实浏览器验收路线。单元测试和生产构建只能证明代码层面可运行，不能替代对 3D 场景、时间轴、城市下钻、势力可读性和历史标签的视觉检查。

## 固定环境

- 浏览器：Chrome 最新稳定版；
- 主分辨率：1920×1080，DPR 1；
- 次分辨率：1365×768，DPR 1；
- 入口：`http://localhost:3000/gpt5.6solultra-history-china3d/`；
- 独立调试入口：`http://127.0.0.1:3043/`；
- 固定 seed：`770`、`221`、`2025`；
- 控制台：保留 Console 与 Network 面板；
- 网络：验收期间不允许项目请求外部域名。

## 启动与静态检查

从仓库根目录执行：

```powershell
npm install
npm --workspace gpt5.6solultra-history-china3d test
npm --workspace gpt5.6solultra-history-china3d run build
npm run sync:check
git diff --check
npm run dev
```

预期：

- 所有命令退出码为 0；
- 根门户能显示本项目卡片；
- 项目 URL 返回页面而非 404；
- 页面资源从项目相对路径或本地依赖加载；
- Console 无错误，Network 无外部域名请求。

## 场景 A：全国总览与势力归属

1. 打开项目，等待首屏稳定。
2. 确认当前年份、关键帧名称、层级、图例和证据标签可见。
3. 缩小到完整中国范围。
4. 旋转、平移和连续缩放相机。
5. 依次选择前 300、前 221、229、1142、1759、2025。
6. 在每帧检查势力颜色、名称、范围、城市标记和事件摘要。

通过标准：

- 全国轮廓和主要地形可辨；
- 同一势力的颜色与图例一致；
- 不同势力边界不出现大面积闪烁、破面或完全重叠；
- 城市标记不会在全国视角遮满画面；
- 关键帧切换后，势力、城市和事件同步更新；
- 古代边界带“史实概括”或“推定复原”提示；
- 2025 帧显示其非 GIS、非法定地图边界。

## 场景 B：城市完整 3D 下钻

选择至少三座地形和时代重点不同的代表城市，例如平原都城、河谷或山地城市、沿海或现代城市群节点。

对每座城市：

1. 从全国视角选择城市并进入。
2. 等待 LOD（细节层级）切换完成。
3. 环绕城市一周，并从俯视降至街区斜视。
4. 检查地形、水系或道路是否影响城市布局。
5. 检查建筑群、时代地标和城市层级是否可辨。
6. 切换到另一个关键帧，再观察同一城市的建筑风格和规模变化。
7. 打开详情，确认史实、推定或程序生成标签。

通过标准：

- 收录城市不是平面图标或单一方盒，而有地形、道路/水系和建筑群；
- 三座城市不会只是改颜色的同一模板；
- 古代帧无现代高层等明显时代错置；
- 程序生成建筑带明确标签；
- 返回全国视角后相机、年份和选择状态不紊乱；
- 下钻过程中无长时间主线程卡死。

## 场景 C：12 帧完整时间轴

1. 回到全国层。
2. 从前 770 开始完整播放至 2025。
3. 在每个关键帧暂停一次，记录年份和名称。
4. 观察势力、疆域、城市规模、建筑风格、地形表现和事件面板是否同步。
5. 播放结束后拖回前 770，再次前进到 2025。

必须按顺序到达：

`前 770 → 前 300 → 前 221 → 2 → 229 → 750 → 1142 → 1279 → 1421 → 1759 → 1912 → 2025`

通过标准：

- 不漏帧、不重复卡死、不倒序；
- 到达关键帧时显示准确名称；
- 两帧之间明确显示“推演中”；
- 播放、暂停和拖动共用同一状态，不出现 UI 年份与 3D 场景不一致；
- 完整播放后可继续操作。

## 场景 D：局部演变

分别执行三个区间：

1. 前 300 → 前 221；
2. 1142 → 1279；
3. 1912 → 2025。

每个区间执行：

- 设置起止点；
- 播放到中点并暂停；
- 向后拖动，再恢复播放；
- 在中间态选择一个势力或城市；
- 到终点后核对事件和建筑风格。

通过标准：

- 只播放所选区间；
- 中间态标为程序化推演；
- 向后拖动可恢复此前状态，而非累积错误；
- 终点与直接跳转到该关键帧的确定性指纹一致。

## 场景 E：世界其他地区

1. 切换至世界或欧亚粗粒度视角。
2. 依次检查前 300、2、750、1279、1759、1912、2025。
3. 在每帧选择至少一个中国以外区域。
4. 查看势力名称、范围、同期事件和证据标签。
5. 返回中国全国层，确认年份保持不变。

通过标准：

- 世界层有区域势力和事件，不是空背景；
- 不要求逐城建筑，但区域范围和名称可读；
- 世界边界同样标明概括或推定；
- 世界与中国层切换不会重置时间轴；
- 不把古代影响范围画成现代精确国界。

## 场景 F：确定性与标签

1. 选择关键帧前 221、城市 A、seed `221`，记录城市指纹或主要建筑数量。
2. 改为 seed `770`，确认只改变允许生成的细节。
3. 再改回 seed `221`。
4. 切换其他关键帧后再返回前 221。
5. 分别选择一个史实概括、推定复原和程序化生成对象。

通过标准：

- 回到相同关键帧和 seed 后指纹一致；
- 势力名称、关键事件等史实骨架不随 seed 改变；
- 三类标签均可看到且说明正确；
- 程序生成内容不显示为确定史实。

## 场景 G：性能与响应式布局

在全国、城市和世界三个层级各观察至少 30 秒：

- 记录 FPS（每秒帧数）、draw call（绘制调用）、三角形和实例数量；
- 快速缩放并连续拖动时间轴；
- 进入和退出城市至少五次；
- 把窗口改为 1365×768 再重复关键操作。

通过标准：

- 控制台错误数为 0；
- 不出现持续下降且无法恢复的帧率；
- HUD、时间轴、图例和详情面板不相互遮挡；
- 主要操作在次分辨率仍可访问；
- 多次进入城市后内存和场景对象数不持续无界增长。

## 自动验收建议

如页面提供 `window.__BENCH__`，建议自动断言：

```js
const bench = window.__BENCH__;
const frames = bench.getKeyframes();
console.assert(frames.length === 12);

bench.setYear(-221);
bench.setSeed(221);
const first = bench.getState();

bench.setSeed(770);
bench.setSeed(221);
const second = bench.getState();

console.assert(first.fingerprint === second.fingerprint);
console.assert(first.isKeyframe === true);
```

具体方法名可以按实现调整，但必须保留等价能力，并在 `HANDOVER.md` 记录。
