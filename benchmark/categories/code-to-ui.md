# 类别规则:code-to-ui — 前端 UI 实现能力

测"模型写**生产级前端界面**"的能力:不是能不能画出来,而是**性能工程、交互细节、健壮性**是否达到工程标准。与 `code-to-3d` 互补:3D 测图形与物理,UI 测 DOM 工程与交互打磨。

## 专项维度(各 0–5)

| 维度 | 测什么 | 评分要点 |
|---|---|---|
| **性能工程 ★** | 虚拟化、防抖 / 节流、rAF 合帧、避免强制同步布局、内存不泄漏 | 大数据量下 DOM 节点数受控、滚动 60fps、防抖节流用对场景 |
| 交互细节 | 拖拽、键盘导航、焦点管理、hover/active 态、滚动体验 | 交互跟手、无迷之跳动、边缘吸附合理 |
| 视觉规范 | 间距 / 对齐 / 层次、色彩系统一致、暗色主题 | 有设计系统感,不是"能看就行" |
| 状态管理 | 过滤 × 排序 × 选中等组合状态正确 | 组合操作后状态不错乱、单向数据流 |
| 健壮性 | 空态 / 超长文本 / 快速连续操作 / 极端窗口尺寸 | 边界不崩不裂 |
| 无障碍 | 语义标签、aria、键盘可达、对比度 | 基本可达性达标 |
| 代码质量 | 模块划分、可读性(加分项) | 不是一坨 |

## 判分方式(客观优先)

本类别**大量约束可自动验证**,评分时优先跑客观检查:

- DOM 节点数上限(DevTools `document.querySelectorAll` 计数)
- 防抖行为:连续输入期间 0 次过滤,停止输入后恰 1 次(页面须显示"过滤执行次数"计数器自证)
- 节流行为:resize 期间处理频率受限
- 帧率:滚动 / 拖拽时 FPS(页面须内置 FPS HUD 自证)
- 排序 / 过滤耗时(页面须显示最近一次耗时)

主观项(视觉规范、交互手感)用 0–5 锚定盲评。

## 常见失败模式

大数据全量渲染 DOM 卡死 / **防抖节流混用或写反**(搜索用了节流、resize 用了防抖) / scroll 监听里同步读写布局导致抖动 / 排序原地突变数组导致选中态错乱 / resize 监听不清理内存泄漏 / 滚动条高度与数据量不符 / 键盘导航与鼠标 hover 打架 / 空态白屏。

## 参数卡要点

固定:数据规模与生成 seed、浏览器与视口、禁用框架 / 组件库与否、防抖节流的目标毫秒数、评测交互脚本(固定操作序列)。
