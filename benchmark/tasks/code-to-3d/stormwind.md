# Mission: stormwind — 奇幻王都全景(内外可穿行)(code-to-3d)

给定"用 Web 3D 复现一座可辨认的奇幻人类王都,并且**建筑内部也要能看**"这一任务,不同模型各自写代码生成场景。
本文件是该 mission 的**冻结规范**:评分时对照此清单,保证同一标准。

**设计意图**:这道题专门压测"外壳之外"的能力。城市外观人人都会做,难点在于
①**空心建筑**(墙体要有真实洞口而不是贴图假门)、②**内外一致的碰撞**(看得见就必须走得进去)、
③**规模下的性能结构**(上百套内景不能把 drawcall 打爆)、④**室内光照**(屋里没有太阳)。
任何一项偷懒都会在"走进最近一栋房子"这个动作里立刻暴露。

## 原始任务描述(冻结 v1 — 2026-07-27)

> 用 Web 3D 技术(Three.js 等通用库允许,游戏引擎导出物禁止)实现一座 3D 奇幻人类王都全景,
> 要求**建筑物内部也可以看**。具体:
>
> 1. **城市结构**:环城城墙(含城门与可登上的马道)、贯穿城区的水系与桥梁、中心广场、
>    ≥2 座地标级建筑(大教堂 / 城堡等)、≥3 个风格可区分的街区。
> 2. **可进入的建筑**:≥30 栋普通建筑必须是真空心 —— 门窗为几何洞口而非贴图,
>    可从街上推门走进任意一栋,内有地板/楼梯/家具/光源;多层建筑可上楼。
>    两座地标必须有完整可进入的大空间(中殿 / 王座厅)。
> 3. **行走系统**:第一人称行走 + 重力 + 跳跃 + 台阶自动抬腿;墙体阻挡与门洞通行必须一致
>    (不允许"门是画上去的"或"墙能穿过去")。另需一个俯瞰全景视角。
> 4. **光照与昼夜**:完整昼夜循环;入夜后窗户/路灯/炉火亮起;**室内白天也要有合理照明**。
> 5. **性能**:桌面 1080p ≥60fps,并说明为支撑上百套内景做了什么工程结构
>    (合并批次 / 分区剔除 / 室内 LOD / 光源池等)。
>
> 约束:禁止加载任何外部二进制资产(模型/贴图/音频),所有几何与纹理必须程序化生成;
> UI 用中文;无控制台报错。

## 公共核心要求

### ① 城市结构

- [ ] 环城城墙 + 城门 + 角楼,马道可真正走上去
- [ ] 水系(运河/护城河)+ ≥3 座桥,水面有动态表现
- [ ] 中心广场(含喷泉/市集之类的场所家具)
- [ ] ≥2 座地标级建筑,体量与形制明显区别于民居
- [ ] ≥3 个可区分街区(材质/层数/业态不同,不是同一套房子换位置)

### ② 可进入的建筑(本题核心)

- [ ] ≥30 栋建筑为真空心,门窗是几何洞口
- [ ] 室内有地板、天花/屋架、家具、可辨认的业态(住家/店铺/酒馆/工坊…)
- [ ] 多层建筑有楼梯且楼板开井,可走上二层
- [ ] 两座地标有完整可进入的大空间
- [ ] 从室内能透过窗/门看到街景(反之亦然)

### ③ 行走与碰撞

- [ ] 第一人称:重力、跳跃、台阶自动抬腿
- [ ] 门洞可通行 / 墙体阻挡,二者由同一份数据保证一致
- [ ] 可站上台阶、楼板、城墙、桥面等多种承载面
- [ ] 具备俯瞰全景视角(自动巡游加分)
- [ ] 不会掉出世界(有兜底)

### ④ 光照

- [ ] 昼夜循环,天色/太阳角度/雾色联动
- [ ] 入夜窗户与路灯亮起
- [ ] 室内白天有合理照明(不能是纯黑)
- [ ] 火光类光源有闪烁等动态

### ⑤ 性能与工程

- [ ] 桌面 1080p ≥60fps,并给出 drawcall / 三角形统计
- [ ] 说明所用的批次合并 / 剔除 / LOD / 光源管理策略
- [ ] 场景可确定性重建(同种子同城市)
- [ ] 运行时统计 HUD
