# Mission: history — 历史地理 3D 演变沙盘（code-to-3d）

给定“从春秋战国到现代，以中国为核心展示城市、地形、建筑、势力版图和时间演变，并以较低粒度补充世界其他地区”的任务，不同模型各自用 Web 3D 技术实现。本文件是该 mission 的冻结规范；后续横向评测必须保留原始需求、关键帧、证据标签和验收口径。

## 原始任务描述（冻结 v1 — 2026-07-24）

> 根据当前仓库的规则，做一个全中国从春秋战国到现代的3D演变沙盘。
>
> 需求如下：
>
> 1. 每个城市都要有完整的3D展示效果，要有地形和具体的建筑物。不确定的地方可以随机生成（但需要符合逻辑）。
> 2. 不同年代要注意不同年代的建筑风格以及如果有朝代要有不同势力的划分，支持放大到全中国地图看势力归属。
> 3. 有一个时间轴，通过年代轴可以看到整个或部分的演变过程（包含势力、地形、国土范围）。
> 4. 另外其他非中国地区也可以做，但可以不需要细到城市，可以看每个时间段的势力版图和大事件。

## 实现口径

本任务采用“**12 个历史关键帧 + 关键帧之间的程序化推演**”，不是逐年 GIS（地理信息系统）数据库、行政边界法定底图、考古级城市复原或历史结论数据库。

- 时间轴允许连续拖动和分段播放，但精确史实只锚定在下表 12 个关键帧。
- 关键帧之间的疆域形变、城市规模和建筑密度变化用于讲述趋势；过渡态必须显示“推演中”或同等提示，不能伪装成某一年的精确史实。
- “每个城市完整 3D”指当前数据集收录的每座代表城市都必须有可进入的地形、道路、水系和建筑群，不以一个平面图标代替。全国尺度使用 LOD（Level of Detail，细节层级）降低开销。
- 中国以外地区只要求大陆级或区域势力版图、名称和重大事件，不要求逐城建模。
- 随机生成必须由固定 seed（随机种子）控制，遵守时代、地形、城市等级和区域气候约束；同一 seed 与关键帧应产生相同结果。

| 序号 | 年份 | 显示名称 | 主要观察重点 |
|---|---:|---|---|

| 2 | 前 300 | 战国七雄·兼并时代 | 七雄势力、城防体系、兼并与交通走廊 |
| 3 | 前 221 | 秦统一·郡县帝国 | 统一版图、郡县体系、驰道与秦式都城 |
| 4 | 2 | 西汉成熟期·丝路贯通 | 汉帝国核心区、长安、丝路节点与边疆联系 |
| 5 | 229 | 三国鼎立·山河为界 | 魏蜀吴分立、山河屏障、军事城市 |
| 6 | 750 | 盛唐都会·四方汇聚 | 长安与洛阳、坊市格局、交通与国际交流 |
| 7 | 1142 | 宋金对峙·南北分治 | 宋金西夏等势力、南北城市差异和商贸网络 |
| 8 | 1279 | 元朝一统·欧亚通衢 | 大一统、行省联系、大都与欧亚交通 |
| 9 | 1421 | 明初迁都·两京格局 | 北京南京两京、明式城池与海陆联系 |

## 证据与不确定性标签（强制）

所有疆域、城市和建筑内容必须可归入以下三类之一，并在详情面板、图例或悬浮提示中可见：

| 标签 | 定义 | 允许的表达 |
|---|---|---|
| **史实概括** | 基于主流史学共识或较明确年代、政权、城市信息，经全国尺度简化后的表达 | 可陈述政权名称、代表城市、重大事件；必须承认边界与城市形态经过概括 |
| **推定复原** | 史料不足、学界存在争议，或为形成连续 3D 场景而作出的合理推断 | 必须使用“约”“推定”“示意”等措辞，不得写成确定事实 |
| **程序化生成** | 由固定 seed 按地形、气候、城市等级和时代风格生成的道路、建筑、植被或过渡态 | 只能作为逻辑一致的视觉补全，不得声称是遗址、古建或逐年疆域复原 |

如实现内部保留 `high`、`medium`、`inferred` 等置信度字段，对外映射规则为：

- `high` / `medium` → **史实概括**，同时可在详情中显示置信度差异；
- `inferred` → **推定复原**；
- 带固定 seed 的生成细节 → **程序化生成**。

## 公共核心要求

### ① 全国尺度与势力版图

- [ ] 可查看完整中国范围，并通过清晰颜色、边界和图例辨认当前关键帧的主要势力。
- [ ] 缩放、旋转和移动相机时，边界、地形与城市标记保持可读。
- [ ] 跨关键帧切换时，势力名称、颜色、范围与事件说明同步更新。
- [ ] 疆域边界明确标为概括或推定，不与现代法定地图混用。

### ② 城市、地形与建筑

- [ ] 当前数据集中的每座代表城市都有三维地形、道路或水系、建筑群和至少一个时代特征地标。
- [ ] 山地、平原、河谷、沿海等地形差异能影响城市布局，而非所有城市复制同一平面模板。
- [ ] 建筑类型、屋顶、城墙、街巷密度、近现代道路与高层建筑随时代变化。
- [ ] 不确定细节采用固定 seed 程序生成，并遵守城市等级、地形与时代风格约束。
- [ ] 全国尺度使用低细节城市符号，进入城市后再加载完整建筑，切换过程不应出现明显卡死。

### ③ 时间轴与演变

- [ ] 时间轴覆盖前 770 至 2025，可选择任意关键帧。
- [ ] 支持完整播放，也支持用户选择起止点进行部分播放。
- [ ] 播放时同步演变势力、疆域、城市规模、建筑风格、地形表现和事件面板。
- [ ] 关键帧之间必须明确标识为程序化推演，不能暗示逐年精确。
- [ ] 暂停、拖动、倍速或分段播放后，场景状态保持一致。

### ④ 世界其他地区

- [ ] 至少提供中国以外的粗粒度世界或欧亚区域视图。
- [ ] 每个关键帧能查看主要区域势力及至少一项相关重大事件。
- [ ] 世界层不要求逐城建模，但边界、名称和事件必须随时间更新。
- [ ] 世界内容采用与中国层相同的证据标签，不确定区域不能伪装成精确国界。

### ⑤ 可控性、可复现与性能

- [ ] 提供中文 UI、图例、年份和当前层级提示。
- [ ] 相同关键帧与 seed 生成相同城市布局；不同 seed 只改变允许程序化补全的细节。
- [ ] 暴露可自动验收的 DOM 标记或 `window.__BENCH__` 接口，能读取年份、关键帧、层级、势力、选中城市和 seed。
- [ ] 桌面 1920×1080 下，全国视角和单城视角均可交互；长时间播放无持续内存增长或控制台错误。
- [ ] 运行时不得依赖外部网络；数据与资源应随项目本地提供或程序化生成。

## 硬性边界

- 不是逐年历史疆域数据库；关键帧间变化是可解释的视觉推演。
- 不是 GIS、测绘或法定边界产品，不可用于现实行政、外交、法律或导航判断。
- 不是考古遗址或单体古建筑的尺寸级复原。
- 现代边界和地名仅作沙盘语境中的概括展示。
- 史实、推定和程序生成必须在视觉上可区分。
- UI 使用中文；页面和控制台不得出现阻断性错误。
- 项目必须维护 `README.md`、`HANDOVER.md` 与 `CHANGELOG.md`。

## 评分与验收环境

使用 `shared/rubrics/code-to-3d.md`。建议权重：

- 需求遵循与历史标签：25%
- 视觉与建筑时代辨识度：20%
- 全国/城市空间层级：15%
- 时间轴与状态一致性：15%
- 技术正确性与性能：15%
- 可控性、可复现和文档：10%

固定验收条件：

- 桌面 Chrome 最新稳定版，1920×1080、DPR 1；
- 再检查 1365×768 的窄桌面布局；
- 分别检查 12 个关键帧；
- 完整播放一次，并执行前 300 → 前 221、1142 → 1279、1912 → 2025 三段局部播放；
- 至少下钻三座不同地形、不同年代重点的代表城市；
- 至少切换两个 seed 并回到原 seed 验证确定性；
- 全国、中国城市、世界区域三个层级均检查控制台错误和帧率。
