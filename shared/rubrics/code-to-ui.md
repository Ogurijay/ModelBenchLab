# 专项评分卡:前端 UI 实现(code-to-ui)

适用于"给同一 UI 工程任务描述,不同模型各自实现"的对比。在通用六轴之上,用下面 7 个专项维度细化。每维 **0–5**,括号为建议权重。

| 专项维度 | 权重 | 评分要点 | 常见失败 |
|---|---|---|---|
| **A. 需求遵循** | 0.20 | 对照该任务的特性清单逐条勾选(见 `benchmark/tasks/code-to-ui/<mission>.md`) | 漏特性 / 只做一半 |
| **B. 性能工程** ★ | 0.25 | 虚拟化 / 防抖节流用对场景 / rAF 合帧 / 无强制同步布局 / 无内存泄漏;以页面内置 HUD 与 DevTools 客观数据为准 | 全量渲染卡死 / 防抖节流写反 / 滚动掉帧 |
| **C. 交互细节** | 0.15 | 拖拽跟手、键盘导航完整、焦点管理、滚动体验 | 交互跳动 / 键鼠打架 |
| **D. 视觉规范** | 0.15 | 间距对齐层次、色彩系统、暗色主题一致性 | 无设计感 / 明暗混杂 |
| **E. 健壮性** | 0.10 | 空态 / 超长文本 / 连续快速操作 / 极端窗口 | 边界崩裂 / 状态错乱 |
| **F. 无障碍** | 0.05 | 语义化、aria、键盘可达、对比度 | div 汤 / 不可达 |
| **G. 代码质量** | 0.10 | 模块划分、单向数据流、可读性 | 一坨 / 全局变量满天飞 |

> ★ **性能工程是本类别的重心轴**,且尽量客观化:要求作答页面内置 FPS / DOM 计数 / 操作耗时 / 防抖计数 HUD **自证性能**,评委用固定交互脚本复核。

## 客观检查清单(B 维判分依据)

- [ ] 大数据量下 DOM 行节点 ≤ 可视行 + 缓冲(任务文档给具体上限)
- [ ] 连续输入期间过滤执行 0 次,停止后恰 1 次(防抖)
- [ ] resize 处理频率受限(节流 / rAF)
- [ ] 滚动 / 拖拽 FPS ≥ 55(1080p 中档机)
- [ ] 长时间反复操作后内存曲线平稳(DevTools Memory 采样)

## 两种模式(都记)

- **模式 A 公平固定**:同一任务描述、禁用框架与组件库、同一浏览器与视口、同一交互脚本。
- **模式 B 各自最优**:允许任选框架 / 库,测生态运用上限。

## 评测环境锁定

- 固定浏览器 + 视口(桌面 1920×1080 / 移动 390×844)、CPU 4× 降速档模拟中档机。
- 固定交互脚本(操作序列 + 时长),录屏与 HUD 数据归档 `benchmark/runs/<date>_<model>/`,匿名盲评。
