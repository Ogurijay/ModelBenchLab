# 专项评分卡:代码生成 3D / 图形场景(code-to-3d)

适用于"给同一任务描述,不同模型各自写代码生成 3D 场景"的对比(即现有 22 个项目)。
在通用六轴之上,用下面 7 个专项维度细化。每维 **0–5**,括号为建议权重。

| 专项维度 | 权重 | 评分要点 | 常见失败 |
|---|---|---|---|
| **A. 需求遵循** | 0.20 | 对照该 mission 的特性清单逐条勾选(见 `benchmark/tasks/code-to-3d/<mission>.md`) | 漏核心特性 / 只做一半 |
| **B. 视觉·审美质量** ★ | 0.25 | 光照真实感、材质、构图、配色和谐、氛围。见下方审美子表 | 塑料感 / 死板 / 脏乱 |
| **C. 技术正确性** | 0.15 | 无控制台报错、无 z-fighting / 穿模 / 闪烁、物理合理 | 报错 / 穿模 / 反物理 |
| **D. 性能效率** | 0.15 | FPS、首屏加载、顶点 / drawcall 效率、移动端可跑 | 掉帧 / 卡死 / 顶点爆炸 |
| **E. 一致性稳定性** | 0.10 | 多分辨率 / 多设备、长时间运行不崩、WebGL/WebGPU 兼容 | 换设备就崩 |
| **F. 可控性交互** | 0.10 | 参数面板、交互响应、可调试性 | 无交互 / 面板失效 |
| **G. 代码质量** | 0.05 | 结构、可读性、可维护性(加分项) | 一坨 / 不可维护 |

> ★ **视觉·审美质量是本 lab 的重心轴**。它同时是"文生图 / 文生 3D 生成质量"和"VLM 审美理解"两类测试的桥梁:把各场景截图喂给 VLM 打审美分,与人工分对比,即可反向测 VLM 的审美判断力。

## 审美子表(B 维展开,各 0–5)

| 子项 | 看什么 |
|---|---|
| 光照 | 方向 / 强度 / 阴影 / 全局光是否可信,时段氛围 |
| 材质 | PBR 质感、粗糙 / 金属 / 透射是否真实,水 / 玻璃 / 泡沫 |
| 构图 | 主体 / 层次 / 引导线 / 留白,镜头是否讲究 |
| 配色 | 色调统一、冷暖对比、不脏不糊 |
| 氛围 | 是否传达出任务要的情绪(如"极端天气"的压迫感) |

B 维得分 = 5 子项均值。

## 两种模式(都记)

- **模式 A 公平固定**:同一任务描述、同一评委、同一评测环境(浏览器 / 分辨率 / GPU),只比模型产出。
- **模式 B 各自最优**:允许各项目用它最擅长的方案(WebGL/WebGPU、库版本),测能力上限。

## 评测环境锁定(公平的前提)

- 固定浏览器 + 分辨率(桌面 1920×1080 / 移动 390×844)、固定 GPU 档位。
- 每个场景固定观察时长(如 30s)+ 固定运镜路径(若有)。
- 截图 / 录屏归档到 `benchmark/runs/<date>_<model>/`,匿名后盲评。
